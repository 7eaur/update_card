# تقرير معالجة فهرسة Update Card — 17 أكتوبر 2026

## مصدر الحقائق
- الملكية: `sc-domain:updatecard.net`.
- المستودع: `7eaur/update_card`، والنطاق الأساسي المعتمد: `https://updatecard.net` **دون www**.
- تقرير **Page indexing** وصورتاه بتاريخ 17 أكتوبر يعرضان مسارات قديمة **دون الشرطة المائلة الأخيرة** مثل `/about` و`/services/games`. هذه ليست النسخ الأساسية المنشورة.
- فحص Google URL Inspection للروابط الأساسية الـ13 أظهر **صفحتين مفهرستين، وأربع صفحات مكتشفة ولم تُفهرس، وسبع صفحات غير معروفة لدى Google وقت الفحص**. قد تختلف أرقام تقرير Sitemap المتأخر عن الفحص الفردي.

## تفصيل حالة Google للروابط الأساسية

| الحالة | الروابط |
|---|---|
| مفهرسة | `/`، `/services/software-licenses/` |
| مكتشفة ولم تُفهرس | `/about/`، `/services/games/`، `/services/subscriptions/`، `/services/digital-payments/` |
| غير معروفة وقت الفحص | `/services/`، `/faq/`، `/contact/`، `/services/social-entertainment/`، `/services/gift-cards/`، `/services/international-shopping/`، `/services/custom-request/` |

## تفسير التحذيرات المصورة
1. **Page with redirect**: ثبت أن `http://updatecard.net/` يُعاد توجيهه بصورة صحيحة إلى `https://updatecard.net/` برمز HTTP 308. نسخة HTTPS الرسمية مفهرسة؛ لا نزيل هذا التوجيه ولا نطلب فهرسة عنوان HTTP.
2. المسارات القديمة مثل `/about` و`/faq` و`/services/games` تعيد التوجيه بشكل صحيح برمز 308 إلى `/about/` و`/faq/` و`/services/games/`. ظهورها في تقارير Google ليس خطأ بالموقع المنشور؛ ويُفضّل أن تزحف Google إلى روابطها النهائية بدل القديمة. لا نضيف الروابط القديمة إلى Sitemap.
3. **Discovered – currently not indexed** على بعض النسخ الأساسية يعني أن Google اكتشف الروابط لكنه لم يزحف إليها أو يفهرسها حتى الآن، ولا يمثل وحده خطأ `noindex` أو `robots.txt`.

## نتائج التدقيق الفني
- أظهر تدقيق الموقع المنشور قابلية فهرسة **13/13**، وHTTP 200، وcanonical ذاتيًا لكل صفحة، وغياب `noindex` عنها.
- ملف `sitemap.xml` يحوي **13 رابطًا أساسيًا**، وقد قرأته Google دون أخطاء أو تحذيرات. أُعيد إرساله عبر GSC Wizard بتاريخ 16 أكتوبر 2026.
- كشف مدقق بنية البيانات عن **نسختين متداخلتين من FAQPage**؛ إحداهما بدون `mainEntity`. عولج السبب بدمج البيانات الإضافية في عقدة صفحة واحدة، مع الحفاظ على `Question` و`acceptedAnswer`.
- حسّنت عناوين صفحات «من نحن»، «الأسئلة الشائعة» و«التواصل»، وأضفت معلومات عملية وأمنية مفيدة للتواصل، وأوصافًا للصور التي تقدم فئة خدمة. أُبقي `alt=""` للصور الزخرفية عمدًا؛ توصيات المدقق الآلية بشأنها ليست عيوبًا فعلية.
- أُضيفت اختبارات CI للروابط الداخلية النهائية (بشرطة مائلة)، وcanonical، والسماح بالفهرسة، وتمثيل FAQPage الوحيد ذي الأجوبة.
- تُعد تواريخ `lastmod` للصفحات المعدلة فقط، ولا تتغير الصفحات الأخرى عشوائيًا.

## إجراءات Google Search Console التي لا تنفذها API العامة
- استخدم URL Inspection للروابط الأساسية المنتهية بـ `/`، ثم **Test live URL** ثم **Request Indexing** للـ11 صفحة غير المفهرسة. لا تقدم الطلب لمسارات `/about` و`/services/games` القديمة غير المنتهية بـ `/` أو للروابط المعاد توجيهها.
- لم يُنفذ طلب فهرسة فردي عبر API؛ Google Search Console URL Inspection API للفحص فقط.
- لا تكرر إرسال Sitemap دون محتوى جديد؛ إعادة الإرسال **لا تضمن** الزحف أو الفهرسة.
- لا تطلب «التحقق من الإصلاح / Validate fix» لتحذيرات إعادة التوجيه الطبيعية، ولا تصفها بأنها فشل.
- راجع بعد التحديث نتائج URL Inspection للصفحات الأساسية، وتقارير Page Indexing وSitemaps وIndexing Tracker، مع إدراك تأخر تحديث تقارير Google.
- إن استمر عدم الفهرسة أسابيع رغم الزحف الناجح، افحص جودة المحتوى الفريد، والتشابه بين صفحات الخدمات، والروابط الداخلية الفعلية الواردة لكل صفحة، ولا تضع كلمات إضافية أو تعدل `lastmod` صوريًا لأجل الزحف فقط.

## معايير القبول
1. بناء ناجح، واجتياز `npm run check` وGitHub Actions.
2. عقدة FAQPage وحيدة وبداخلها جميع أسئلة `mainEntity` مع `acceptedAnswer`.
3. Sitemap وcanonical والروابط الداخلية تشير مباشرة إلى 13 عنوانًا نهائيًا، بلا إدراج نسخ HTTP أو www أو دون `/`.
4. التوجيهات 308 القديمة تظل فاعلة، فلا تحدث صفحات مكررة.
5. إعادة فحص الإنتاج بعد النشر؛ **الفهرسة الكاملة من Google ليست شرط نشر يمكن ضمانه**.

> هذا المستند حالة فحص وإصلاحات برمجية، وليس شهادة بأن Google فهرس جميع الصفحات.
